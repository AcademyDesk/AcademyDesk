## Selected immediate course

1. Keep the failed candidate inactive. Manual ERP correctness/fallback and independent
   application work continue; never pretend that all conversational actions are live.
2. Obtain designated independent semantic/privacy/provenance review, correct/expand
   development examples, then issue new hash-bound receipts for every changed artifact.
   The current 56 are a small review curriculum, not a production-scale training corpus.
3. Prepare one concrete resource/adapter experiment proposal only after data review:
   exact source revision/checkpoint/tokenizer identities, compatible isolated trainer,
   bounded steps/time/disk/RAM/VRAM and failure/stop/rollback plan. Compare against
   unchanged scoring and independent fresh full-plan/safety cases.
4. Ask for scoped acquisition/training/resource approval before executing it. Do not
   download the absent shards now, install a trainer into the embedding environment,
   relax memory guards, restart Docker or provision Azure to make a readiness report pass.
5. A completed experiment is still not a release. Require artifact conversion/identity,
   original regression, fresh semantics/injection/safety, budget and restoration proof,
   then actual linked host/API/SQL/browser authorization and domain acceptance.

An adapter experiment is the current improvement candidate, **not a guaranteed fix**.
Do not buy a VM/SKU from the weight-byte count alone. Production sizing is separate.
If the experiment is not approved or fails, retain the unavailable boundary and
present measured alternatives; never silently switch tiers or a larger model.
