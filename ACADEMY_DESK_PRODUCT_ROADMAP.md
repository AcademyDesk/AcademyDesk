## Outcome and operating rule

Build **Academy Desk PENTA AI** as an enterprise-grade, AI-native SaaS application before a public marketing site. Pulse, Executor, Navigator, Twin and Autopilot share one protected intelligence platform above the existing deterministic academy domain. The owner's current target is **90% AI-assisted/approved-automated eligible operations, 10% manual control**, measured as completed authorized workflows rather than model-call counts. This is a future outcome, not current automation. The LLM never owns unrestricted SQL, permissions, accounting or execution.

Deliver one meaningful vertical feature at a time: requirement → domain/source → business rule → API → role/tenant policy → frontend → disposable SQL/HTTP → real browser/mobile → regression/security → owner review → feature-branch push → approved merge → gated Azure release. A tested backend read is **partial**, not a completed user feature. Keep a local frontend/API/disposable-SQL environment usable where practical, and preserve manual workflows when PENTA is disabled.

These are delivery packages, **not nine small jobs or a fixed completion estimate**. Each contains domain-specific acceptance tasks. Finance/refund/credit-note/payroll/security/destructive actions need their existing specialist business-policy gates before conversational execution. Public marketing is deferred until claims match accepted capabilities. Do not remove manual access to create an artificial 90% ratio.

### Quality and progress measurement

Track eligible workflow completions through AI assistance/approved automation versus manual, task success/corrections/fallbacks, grounded answer correctness, tool/argument accuracy and median/p95 latency. Confirmation remains human oversight. Future feedback must be minimal, tenant-scoped and privacy-approved; metadata hooks do not enable training.

Target zero unauthorized disclosure/execution and no ungrounded financial facts. Use representative held-out academy conversations (including typos, paraphrases, multi-field input, duplicates and changed state), not repeated examples, to establish capability. The private 2B planner is not proven equivalent to a general-purpose frontier assistant. Model/context improvements follow failed-case evidence in the existing Mini project; no bigger-model assumption or new inference engine.
