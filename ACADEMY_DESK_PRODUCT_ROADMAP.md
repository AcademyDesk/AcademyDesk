# Academy Desk product delivery roadmap

Status: active direction, 2026-10-04. This coordinates existing work; it does not replace [enterprise testing](ENTERPRISE_TESTING_ROADMAP.md), [QA release gates](QA/09_RELEASE_GATES.md), the [PENTA architecture](PENTA_ARCHITECTURE_DECISION.md), or historical reports. GitHub `main` remains the accepted product line; this feature branch is not a release.

## Outcome and operating rule

Build **Academy Desk PENTA** as an enterprise-grade, AI-native SaaS application before a public marketing site. Pulse, Executor, Navigator, Twin and Autopilot share one protected intelligence platform above the existing deterministic academy domain. The 80–90% AI-assisted/approved-automation ambition is a measured future outcome, not a claim of current capability. The LLM never owns unrestricted SQL, permissions, accounting or execution.

Deliver one meaningful vertical feature at a time: requirement → domain/source → business rule → API → role/tenant policy → frontend → disposable SQL/HTTP → real browser/mobile → regression/security → owner review → feature-branch push → approved merge → gated Azure release. A tested backend read is **partial**, not a completed user feature. Keep a local frontend/API/disposable-SQL environment usable where practical, and preserve manual workflows when PENTA is disabled.

## Immediate sequence

1. Preserve the validated AI1-S1a/b read contracts and enterprise QA evidence. Review the whole branch for credentials/unrelated generated files, then push the validated feature branch normally; do not merge it merely because it is synced.
2. Use the v0 handoff for the first significant PENTA workspace design. Then implement one **local, default-off, admin-only** read-only user journey with the real API, truthful source links and manual fallback. No customer data is sent to an AI provider at this point.
3. Run browser/mobile, permission, tenant, input, source, empty/error, audit-fault and regression checks. Show the owner a local feature checkpoint. Record remaining gaps rather than labeling a partially tested screen ready.
4. Continue enterprise P0/security/finance work in parallel. No merge or Azure release until the relevant gates and human checkpoints pass.

Planning status is not feature completion. The current PENTA branch can be shared on GitHub as a feature branch without being accepted into `main` or deployed.
