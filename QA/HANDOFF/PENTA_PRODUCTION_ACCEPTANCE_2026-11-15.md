## Measure conversation by verified outcomes

The launch target is 90% of eligible first-academy outcomes completed through
conversation. Count each role and outcome once. A supported read needs the
correct authorized data. A write needs its required confirmation, the actual
domain effect, an audit and recoverable confirmation. The denominator must
come from the first-academy workflows in
[PENTA host implementation status](../../PENTA_HOST_IMPLEMENTATION_STATUS.md).
The current guided browser results are evidence for the host and UI. The
private Mini evaluation and the qualifying numerator remain open.

| User request | Required production behavior |
| --- | --- |
| Supported wording and ordinary paraphrases | Resolve the intended eligible workflow and complete it with verified data. |
| Missing details, multiple matches or a follow-up referring to the wrong record | Ask a specific question, keep the correct scope and wait for the answer. |
| User corrects a name, date, amount or target | Discard the superseded plan and require review of the corrected terms. |
| User asks for an unavailable or unauthorized operation | Explain the boundary and present an allowed next step. |
| Private model or academy service is unavailable | Show an accurate state, preserve authorized Manual access and let the user recover the same pending action. |
| Lost response or retry | Reconcile the original request and show its receipt. Domain effects, audit and notifications must agree. |

The real Mini evaluation begins with learner search and follow-up through
its existing bridge. Run fresh held-out prompts through the pinned private
model and exact host before expanding the tool catalog. Include paraphrases,
misspellings, ambiguous references, user corrections, cross-tenant attempts,
bad tool arguments and provider failures. Evaluate the actual outcome,
including the correct refusal or clarification when required.
