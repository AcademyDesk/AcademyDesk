### Reproduced UI defect

The original component tied cleanup to `url`, but its React state continued to
belong to the same component instance. Replacing fileA with fileB revoked A's
object URL while retaining its preview DOM/state under B's title. A cancelled
A request or completed native download could also leave its status message on
B. An external-link round trip could restore stale preview state.

The isolated actual-component Chromium runner reproduced12 failures out of16
groups; four Close/unmount controls passed. The same4PASS/12FAIL result was
retained after explicitly setting the fixture document's UTF-8 encoding.
These are UI state/lifetime defects, not a new server authorization bypass.

The exported component now renders its stateful file-action child with the
private file URL as its React identity. A replacement therefore removes the
old preview and state, aborts its pending action, revokes its object URL and
removes its native targets. Old asynchronous callbacks belong to the removed
instance and cannot update the replacement's busy/message state. Same-file
close, retry, download and title updates retain their existing behavior.

The application change is nine added lines and one replaced line. No shared
session, permission, tenant, storage, ticket, range or download protocol changed.
Authenticated access remains independently enforced by the server.
