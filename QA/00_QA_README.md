## Permanent IDs

`DOMAIN-LAYER-NNN` identifies a scenario, not a particular test runner invocation. Examples: `AUTH-001`, `TEACHER-FORM-001`, `FINANCE-RULE-001`, `UI-DROPDOWN-001`, `SECURITY-ROLE-001`. Generated endpoint/route/form scenarios have IDs allocated in [registry.json](registry.json); allocation keys are saved permanently. Never renumber existing cases; retire a case and retain its ID if the underlying feature disappears. If a route or handler is renamed, migrate its registry key while preserving its ID. Dataset/browser/viewport variants are run parameters, not new permanent test IDs. Source line numbers are audit anchors and can change.

Issue IDs use `BUG-FUNC`, `BUG-API`, `BUG-DATA`, `BUG-UI`, `BUG-SEC`, `BUG-PERF`, followed by four digits. Reserve each ID permanently. Bug severity describes impact; bug priority is triage order; test priority describes release importance. These are separate fields.

## Evidence and issue lifecycle

Store synthetic/redacted evidence under `EVIDENCE/<kind>/<run-id>/`; retain original check outputs under `EVIDENCE/logs`. Never commit access/refresh tokens, passwords, connection strings, actual customer forms, or production database dumps. Source manifests store hashes, not configuration contents. Screenshots require synthetic accounts or redaction.

An issue remains OPEN until original reproduction → understood cause → fix commit → original case passes → regression added → module suite passes → critical regression passes → documented retest. A code change or build success does not close an issue. Phase 1 deliberately closes none.

Confirmation status is separate from OPEN/CLOSED: STATIC-FINDING → RUNTIME-REPRODUCED → FIX-IN-PROGRESS → FIXED → RETESTED → VERIFIED → CLOSED. Each transition requires new linked evidence. RUNTIME-REPRODUCED for BUG-FUNC-0004 refers only to the executed lint failure, not a business workflow. Never promote a source hypothesis because another related test passed.

Stop after Phase 1 review. No deployment, business-logic repair, golden-image approval, or bulk test implementation is part of this phase.
