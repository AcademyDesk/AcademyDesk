## G03 — admin access and mutation outcomes

All reviewed PlatformControl actions require Authorize and IsPlatformOwner flag. Role-name-only PlatformOwner, ordinary Owner/AcademyAdmin, custom permission and teacher/student/guardian actors must deny. No academyId argument on these actions means the global academy filter does not supply the owner check; explicit flag check is essential. Test anonymous/inactive Identity, active flag-only owner and cross-tenant targets that a real platform owner is authorized to manage. Own AuthSession profile/password/image actions work for the signed-in user by identity and do not accept a target user ID.

Admins lists users in AcademyAdmin role, ordered display name, including inactive/unassigned users and academy names. UI academy count deduplicates names rather than IDs; test duplicate-name academies. SetAdminActive checks target role, updates Identity then writes platform audit in the separate domain context. ResetAdminPassword checks nonblank/min8 and target role, uses generated reset token internally, checks result then domain audit. Failures after Identity commit can produce error with actual changed state; test fresh Identity, sign-in/token behavior and audit separately. No claim of transaction across contexts or automatic preservation of a last administrator.

Settings get/save and Health call GetSettingsRecord. Empty table inserts default settings during GET; multiple rows cause deletion of all but latest updated/created row during GET. No unique singleton key is mapped. Test concurrent reads/updates, competing singleton insert, stale record selection and write failure; record side effects and do not treat these endpoints as pure health probes. Save validates before helper, assigns properties, adds audit and saves. Health queries settings before CanConnectAsync, so an unavailable DB may throw before it can return Database=Unavailable. API=Operational is hardcoded on a successful response, BackgroundJobs/CommunicationProviders are Not configured. UI must distinguish failed/stale health from operational evidence.

## Announcement producer → consumer

CreateAnnouncement validates owner, academy, title/message and hours, then stores Academy recipient with no recipient ID, InApp, Sent and UTC timestamp. Metadata contains important=true, expiry UTC and audiences=Admin. Notification and platform audit save together. Sent is database state, not proof a browser displayed the message. No external sender is used in this path.

Platform list queries100 latest academy notifications before applying HasAdminAudience, and uses substring Contains(Admin), not an exact audience token. Expiry reader and audience reader assume object/string JSON and catch only JsonException; extend existing BUG-API-0004 tests for wrong JSON kind/property types. Invalid dates also need UI Intl formatting tests. UI shows first12 recent entries and counts active using Date.now at render, with no clock-driven refresh; test expiry while idle and newer nonadmin messages starving older admin messages.

Portal.Announcements chooses Student if StudentId, else Teacher if TeacherId, else Admin. This classifies Guardian-only and other unlinked users as Admin without checking administrative role (BUG-SEC-0009). It scopes notifications to user's AcademyId, filters non-Cancelled and then takes10 before expiry/audience checks. Test guardian, actual admin, teacher/student, unlinked account, dual links, foreign academy, inactive Identity, revoked guardian link and suspended academy. The owner-only producer plus explicit Academy administrators UI establishes intended audience; same-tenant access is not sufficient for that audience.

Enterprise shell fetches /api/portal/announcements on mount, every30seconds and window focus. Successful array replaces state, failed fetch retains old entries. Notification button displays count/list; important banner repeats text for scrolling. Verify new announcement appears at next successful poll/focus, expires, remains escaped/readable and has correct academy/audience. Test ten-candidate starvation, offline stale banner, focus/navigation, no announcements and repeated mounts with interval cleanup. Reuse PortalController completed mapping; this is an added targeted permission case, not a new controller count.
