## Billing lifecycle and reconciliation

CreateInvoice produces Draft with number, amount, currency and date range. Owner list joins academy and orders due date descending. Academy BillingInvoices returns every same-academy status including Draft; UI offers Submit payment for Draft/Issued/Overdue and unknown statuses, hides action for Paid/Void, and shows submitted badge for Payment submitted. API rejects only Paid/Void, so Draft and repeated Payment submitted requests are accepted. Document draft visibility/submission and transition policy for approval; do not silently assume a published-only contract already exists.

SubmitPayment records a claim/reference and timestamp, not a transfer, payment-provider verification or actual collection. Repeats replace reference and submitted timestamp. Owner status selector offers Draft/Issued/Payment submitted/Overdue/Paid/Void. API accepts any trimmed status, sets PaidAtUtc only for exact Paid, otherwise clears it. Repeat Paid resets timestamp; reversing Paid/Void is not blocked; payment reference/submitted timestamp remain. Test allowed transitions and exact casing, unknown/empty/null, replay, two concurrent actors and fresh readback. Owner manual verification may be intended; approve transition rules before repair rather than inventing an external payment integration.

Overview TotalBilled excludes Draft/Void; CollectedBilling includes exact Paid; OutstandingBilling includes only Issued/Overdue. A normal payment submission leaves its amount billed but neither collected nor outstanding, with no pending monetary balance (BUG-DATA-0024). Specify a single-currency INR1000 issued -> submitted -> paid fixture plus void/rejection controls and independent expected totals. Platform control Open invoice count includes Draft and Payment submitted because it excludes only Paid/Void; distinguish record-count labels from monetary totals. Overdue count is exact status, not computed from DueDate. Test date-boundary cases without claiming an overdue worker exists.

All platform amounts are aggregated without currency grouping; Overview UI formats as INR. Extend BUG-DATA-0016 instead of duplicating it: INR1000+USD100 must never be presented as INR1100 without an approved conversion policy. Owner and academy invoice rows preserve explicit currency; owner modal uses rupee icon even for other currencies, so include visual unit consistency. Test decimal rounding/readback independently of displayed formatting. Counts for ActiveStudents use student IsActive without excluding inactive academies; define denominator in label/policy. Plans groups all academies; RecentAudit is eight latest events, not full history. Overview loading/error must not appear as verified zero totals.

## Support lifecycle and triage

CreateSupportCase defaults Open. Owner requires academy+subject; academy requires subject+description. Lists return all statuses; owner orders creation descending, academy updated-or-created descending. Owner UpdateSupportCase accepts freeform status/priority, sets ResolvedAtUtc for exact Resolved/Closed else null. Repeated closure resets time and reopening clears it. UI offers Open/In progress/Resolved/Closed, preserves existing priority when changing status and has no priority edit in that row. Test casing/unknown/null/oversize, closure/reopen races, row identity, stale updates and exact audit/readback.

Academy RespondToSupportCase rejects only exact Resolved/Closed, overwrites one AcademyResponse with trimmed message and timestamps. UI labels this Your latest response; it is not an append-only conversation or bidirectional chat. Test second update, loss of unsent text on error/reload, concurrent replies and closing while composing. Approve history/notification requirements separately; no delivery provider is present here.

Owner High priority count/modal filter accepts High/Urgent only, omitting producer Critical (BUG-FUNC-0011). Fixture matrix Low/Normal/High/Critical/Urgent across Open/In progress/Resolved/Closed must reconcile both count and modal membership. All cases visibility does not compensate for a missing triage result. Resolved includes closed, Open excludes both. Test empty and large lists, long text and updates from the other portal.
