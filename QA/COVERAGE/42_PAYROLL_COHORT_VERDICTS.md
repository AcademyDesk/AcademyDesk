## Cross-row reconciliation and distinct findings

`CreateProfile` checks the supplied TeacherId only when non-null, while `UpdateProfile` checks neither worker link; shared `Valid` enforces no identity-link invariant. Existing BUG-DATA-0009 already covers both and is **not duplicated**. `Pay` permits deductions greater than gross, creating negative NetAmount; existing P0 BUG-DATA-0003 covers it. `Pay` has no unique `(academy,profile,period)` key or idempotency token; repeated clicks can create separate payout rows. Period labels are free text, so duplicate/overlap policy needs business approval before claiming a product defect. Generated payslip number has a unique index but no collision retry. These are explicit runtime and policy gates.

**New BUG-DATA-0056 / PAYROLL-HISTORY-IDENTITY-001:** Payouts joins historical rows to the *current* mutable profile for worker name/type. UpdateProfile can change those fields, so a prior payout's returned identity changes; absent profile drops it from the list. PayrollPayout has no worker-name snapshot. Test with synthetic before/after SQL and reconcile a historical payslip number; do not execute real payroll.

**New BUG-FUNC-0033 / PAYROLL-PRINT-001:** Each row's Print / Save PDF merely calls `window.print()` without selecting a payout or rendering a payslip. The global print rules hide all `body` descendants except `.invoice-paper` or `.certificate-preview`; `/payroll` renders neither. Source predicts a blank print document, but actual browser print/PDF output remains NOT RUN. The register itself also omits payslip number, gross and deductions, so printing the whole page would not be a complete row-specific payslip even if visible.

G03 matches Batch 01: PayrollController is not in PermissionCatalog, so an ordinary FinanceUser/custom `finance.manage` user is denied by the full academy filter despite a Finance module; active same-tenant Owner/AcademyAdmin with Finance enabled passes, and an active flagged PlatformOwner bypasses filter checks. The page additionally depends on Teachers and Staff read APIs. Role string alone is not the platform flag, and direct-controller behavior is not full-pipeline authorization proof. Every allowed/denied branch needs no-write and scoped-read assertions with isolated identities.
