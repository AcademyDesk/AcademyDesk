## G02 — COMPLIANCE-FORM-001 branding and independent logo upload

`load()` requests first academy, its students, all batches, certificates and branding in one `Promise.all`. Any non-OK response blocks the page and reports only “Certificates could not be loaded”; one optional lookup is not isolated from the other three. Branding's color/signatory fields are controlled drafts. `saveBranding` sends a JSON **PUT** containing only `accentColor` and `signatoryName: branding.signatoryName || null`; it does not read FormData. `Change logo` opens a visually hidden file input and its `onChange` **POSTs immediately**, independently of Save branding. There is no `required` attribute for any branding field.

| Control / initial display | Wire → API normalization → stored value | Boundary and state variants |
| --- | --- | --- |
| Logo file, initially none; `accept` PNG/JPEG/WebP | Multipart `logo` to UploadLogo (COMPLIANCE-API-004). API checks nonempty and ≤2,500,000 bytes, filename extension `.png/.jpg/.jpeg/.webp` and claimed matching ContentType; writes random filename under `wwwroot/academy-assets/{academyId:N}/certificates`, then sets Academy.CertificateLogoUrl | File picker cancel/no-op, 0/1/2,500,000/2,500,001 bytes, mismatch/spoofed content, unsupported extension, wrong route academy, interrupted copy/failed DB save/orphan or older file, repeat upload, anonymous/foreign static GET and cache. `accept` is a picker hint, not byte validation. Existing SECURITY-FILE-001/BUG-SEC-0001 applies to direct static delivery |
| Accent colour, controlled HTML color, default `#0F6CBD` | JSON `accentColor`; API matches exactly `^#[0-9A-Fa-f]{6}$`, uppercases valid value, otherwise stores **null**. GET projects null back to `#0F6CBD` | UI color selection, direct API missing/null/invalid/short/long/mixed-case, old accent cleared, reload/preview color. Invalid values are silently normalized, not 400 |
| Authorised signatory, empty draft | JSON `signatoryName` or null; API `Clean` returns null for whitespace, otherwise trims and **truncates** at 140 chars; Academy.CertificateSignatoryName nullable | Empty/space, 139/140/141, Unicode and long combined graphemes; verify readback/preview. Client has no `maxLength`, server truncates rather than rejects |

Upload success replaces `branding` and announces “Academy logo uploaded.” Upload failure uses a fixed size/type message even for 401/403/404/500/network; file input is reset in `finally`, so retry requires repicking. The hidden input has no direct label; the Change logo button is the visible trigger and needs keyboard/focus verification. Save branding uses `savingBrand` for both operations, disables its button while pending, and reports a single status. HTTP OK updates the returned branding; non-OK preserves the controlled draft and shows a generic message. A simultaneous upload/save can reorder responses and overwrite visible branding with older returned data; persisted fields are separate. Test this as a state race, without presuming a DB overwrite. Local branding changes are **not** protected before Issue or navigation. There is no UI logo remove action; a fresh upload can leave the prior file. SQL/file success and rollback must be asserted separately.

## G02 — COMPLIANCE-FORM-002 issue and printable preview

`issue` sends JSON to POST `/certificates` (COMPLIANCE-API-005) with `studentId`, `batchId: batchId || null`, `title`, `templateKey: themeKey`, `issuedDate: issuedDate || null`, `notes: notes || null`. It sends no `designKey` or artwork coordinates; API accepts only design `none` and stores fixed artwork 50/30/72 even if a direct caller supplies otherwise. The rendered theme list has 21 keys matching the case-insensitive API allowlist. Initial theme is `music-recital`; API defaults to it if omitted/null. No per-student batch filtering exists in the UI.

| Control / initial state | Wire → `IssueCertificateRequest` → storage | Boundary and conditional cases |
| --- | --- | --- |
| Student select, initially empty then loader selects first returned learner | Required Guid. API checks only same-academy `Students.Any`, not active or current enrollment; stores StudentId | No students/no-op, stale ID, missing/foreign/inactive learner, two-academy filter, access-denied lookup, automatic first-student selection. Selector has no native `required` |
| Class / batch select, empty | Optional Guid or null; API checks only same-academy existence, then stores BatchId | Independent programme/null, selected batch unrelated to student, inactive/history, foreign/missing/stale batch. Existing BUG-DATA-0046 / CERTIFICATE-ENROLLMENT-001 governs relationship mismatch |
| Certificate title, initial `Certificate of Achievement`, HTML required | Raw string; API rejects blank/whitespace then trims; `Certificate.Title` required max 250 | 0/space/249/250/251, Unicode, missing/null direct API and browser required; oversized title has no explicit server length response before SQL constraint |
| Issue date, blank | Nullable DateOnly; API defaults to **UTC current date** when omitted; stored IssuedDate | Year selection/leap/malformed direct API, past/future, midnight local-vs-UTC, blank default and readback. Draft preview instead uses browser local `new Date().toLocaleDateString('en-IN')`, so an empty-date preview can differ at midnight |
| Certificate theme, initial `music-recital` | String from 21-option list; API case-insensitive allowlist, stores trimmed lower-case key; required `TemplateKey` max 60 | Each group/key, direct API unknown/blank/case/missing, persisted key vs CSS class, unavailable legacy theme label. API rejects empty key, defaults only null/missing |
| Recognition note, blank | `notes || null`; API `Clean` makes blank/space null, trims and truncates at 2000; nullable Notes max 2000 | 0/1999/2000/2001, whitespace/Unicode, preview does not display note even when it will be saved; later family certificate projection does include Notes |

Issue generates a certificate number `CERT-{UTC second}-{3-digit random}` and 16-character verification code, status Issued, plus an explicit audit row in the same SaveChanges. Unique `(AcademyId,CertificateNumber)` index exists but there is no collision retry; test rapid/concurrent issue, duplicate taps and rollback/no-audit on rejection. The status API is a separate action, not a page control: it accepts Issued/Revoked/Replaced case-insensitively, stores the caller's trimmed casing and appends an audit row. UI only displays status, no revoke/replacement control. Public verification should reflect real stored status; do not infer that a browser preview is a verified certificate.

**Distinct finding BUG-FUNC-0032:** `Print / save PDF` calls `window.print()` on the *current editable draft* and print CSS renders `.certificate-preview` full-page. There is no Issue prerequisite, saved-row selection, certificate number, verification code or status in that preview. Before issue, after a rejected issue, and after modifying a previously issued draft, it can print apparently official content that has no matching register/verification record. Retest with synthetic records and captured print/PDF output; this is separate from BUG-DATA-0046's incorrect batch attribution.

After a successful POST, `issue` clears notes/date and sets “Certificate issued and ready to print,” then `load()` clears that notice (existing BUG-FUNC-0003). It also retains student/batch/title/theme, so a second click can issue another credential. HTTP non-OK gives the same generic “Check required details” for any cause. Transport exception and a failed post-commit `load()` are uncaught: the record may exist while UI implies failure or remains stale. Probe rejected status, timeout/unknown commit, committed-then-GET failure, duplicate requests and safe fresh register verification before retry. `load()` overwrites branding/list and can race earlier requests; it does not reset studentId if it becomes stale. Print should be tested at desktop/mobile/zoom for cutoffs and provenance, not marked PASS from CSS inspection.
