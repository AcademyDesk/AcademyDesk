## Common effective gate — implemented behavior, not approved policy

The global academy filter receives an `academyId` route argument for every action here. An unresolved/anonymous user returns 401. Program's inactive-Identity middleware returns 403 before the filter (including a flagged platform owner). An active `IsPlatformOwner` **flag** bypasses tenant, academy-active, module and permission checks and generic filter audit; the role name `PlatformOwner` alone does not. Every other caller must have `ApplicationUser.AcademyId == academyId` and an existing active academy; a missing/inactive academy yields 403. Module check precedes the Owner/AcademyAdmin bypass. Owner/AcademyAdmin then reach action-local validation; ordinary users need the mapped permission through a system role, custom-role permissions or an active, unrevoked grant. If the controller has no mapping, the ordinary caller is denied before grant evaluation, even if holding every listed permission. An administrator holding multiple roles takes the administrator path. Use real HTTP/Identity/SQL to verify these results; direct-controller tests cannot establish filter behavior.

| Controller / module / catalog | Same-tenant active Owner or AcademyAdmin | Ordinary same-tenant role or grant | Platform flag |
| --- | --- | --- | --- |
| Certificates / `Certificates` / **no mapping** | All six actions if module enabled; no separate issue/status role | All denied, including Teacher, Student, Guardian, `workforce.manage` and any custom grant | All six reach action guards across route academies |
| AuditLogs / `Core` / **no mapping** | List and CSV export; Core always passes the module check for an active academy | Both denied even with `reports.export` or `settings.manage` | Both reach action query |
| AcademyExports / `AccessGovernance` / `reports.export` | Export if AccessGovernance enabled | Only `reports.export` with AccessGovernance enabled; FinanceUser system role includes this permission. A Finance module alone is insufficient | Export reaches resource switch across route academies |
| Expenses / `Finance` / `finance.manage` | List/Create/Update if Finance enabled | `finance.manage` with Finance enabled; FinanceUser system role qualifies; reports.export alone does not | All three reach action guards |
| AdminWorkItems / `Core` / **no mapping** | List/Create/Status/CollectionState on active academy | All four denied, including Manager, Operations and FinanceUser despite their work or finance roles and any grants | All four reach action guards |

Foreign/unassigned academy is 403 for ordinary users in every row. A non-platform administrator is also denied if the required non-Core module is absent, despite the admin role. Expired/revoked/nonmatching grants do not satisfy mapped permissions; a valid grant does not bypass tenant/module/active checks. Denied writes must cause no domain, file or audit side effect. Generic audit applies to successful admitted non-platform mutations, not to reads, but full-pipeline verification is needed for action-returned 400/404 and audit write failures (API-RELIABILITY-001). No endpoint below has an additional local role check. Route-scoped lookups remain in force for flagged-platform callers wherever specified below.
