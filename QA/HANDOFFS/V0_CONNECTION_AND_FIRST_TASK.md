## First design task to give v0

Design a premium, responsive **PENTA read-only command workspace** within the existing Academy Desk SaaS shell, not a generic chatbot and not a public marketing site. Start with the real, current Executor use case: an authorized Academy Owner/Admin searches recorded active students or batches and receives bounded, source-backed matches. Make the current limited capability feel useful and honest. Show the five PENTA names as product architecture, but do not present Pulse, Navigator, Twin or Autopilot as enabled functions before implementation.

Produce desktop and narrow-phone layouts, light and dark themes, and the interaction states below. Use clear information hierarchy, generous but efficient spacing, polished cards/typography, touch targets, visible input labels, keyboard focus, screen-reader status and reduced-motion behavior. Fit the established colors/tokens and navigation rather than replacing the whole application shell. Design a local/manual fallback and a clear “PENTA preview”/availability message.

### Actual contracts available now

| Operation | Request | Current result and truth constraints |
| --- | --- | --- |
| Academy context | `GET /api/academies/{academyId}/penta/academy-context` | Own active academy name/country/timezone, source and UTC as-of. |
| Student lookup | `GET /api/academies/{academyId}/penta/student-search?q={2..80 chars}` | At most 10 active student IDs/display names/active flags and Student 360 source paths; `hasMore`, source, timezone and UTC as-of. No guardian, medical, contact or finance fields. |
| Batch lookup | `GET /api/academies/{academyId}/penta/batch-search?q={2..80 chars}` | At most 10 active batch IDs/names/codes, `/batch-setup` list path, `hasMore`, source, timezone and UTC as-of. No schedule, capacity, teacher, room, meeting link or notes. |

All are default-off, Development/Testing-only, own active academy, current active Owner/Admin. Teacher, student, guardian and platform owner are denied in this pilot. No current natural-language model orchestration of these search endpoints, no live AI response, no write, and no external provider processing of customer data. The design must not imply otherwise. Use synthetic names/codes only.

### States to design

1. First visit: purpose, two explicit search choices (Students / Batches), concise examples, “recorded data” explanation, manual navigation.
2. Query entry, submit, loading and cancellation; input 2–80 characters; safe handling of rapid repeat searches.
3. One result, several same-name results requiring user choice, no result, 10-row truncation/`hasMore` without pretending all matches were fetched.
4. Result card shows record type, exact name/code, source, as-of and a truthful action: “Open Student 360” versus “Open batch list”. Never claim a batch-specific destination. Do not invent available seats, fees, upcoming classes or recommendations.
5. Disabled/unavailable, unauthorized, expired session, academy inactive, API/network error and audit failure. No raw internal error or false success; existing manual pages stay reachable when permitted.
6. Responsive navigation on narrow screens without overlays obscuring results, scrolling traps or clipped dropdowns; keyboard-only and screen-reader announcement examples.

Deliver a small design system/specification plus component/page concept suitable for integration into the existing Next.js static-export app. Separate **current functional states** from clearly labeled future Pulse/approval/inbox concepts. Show interaction notes and accessibility annotations; do not hard-code credentials, real student data, fake payment totals, fabricated PENTA activity or an actual provider connection.
