# Phase 2B — Explicit message/banner channel

2026-10-01; accepted [BUG-FUNC-0026](../ISSUES/BUG-FUNC-0026.md), COMMUNICATION-CHANNEL-001. One bounded local repair, Sol High; accepted Astra finding reused. Issue/Phase2B remain OPEN, not delivery/release acceptance.

## Repair and preserved behavior

Two product sources changed: `apps/web/src/app/communications/page.tsx` and `apps/api/Controllers/NotificationsController.cs`.

The form detaches the template when switching to/from Portal banner or explicitly choosing an incompatible channel. It retains the visible composed message with the entered variables resolved, clears hidden template/variable state, and clears the prior recipient. Compatible direct-person switches keep the template but require a new recipient. Banners always submit InApp/null template and audience-only variables, even if stale hidden state is injected. A stale incompatible direct template blocks submit with guidance instead of silently changing delivery.

The API rejects explicit requested-channel/template conflicts before writing, plus important Academy banners with an external channel or template. Banners use canonical InApp. Matching templates still supply missing title/body and interpolate variables; unspecified/blank channel retains the legacy template-channel fallback for non-banners. IsActive/own-academy template availability, duration limits, existing consent/connection checks and complete response contract are preserved. No DTO/schema/security/module/role/transport/portal reader/template-status or marketing-consent policy change. Case-insensitive matching and surrounding request whitespace remain supported. Current Draft/Approved/Disabled template status policy is not addressed by this slice.
