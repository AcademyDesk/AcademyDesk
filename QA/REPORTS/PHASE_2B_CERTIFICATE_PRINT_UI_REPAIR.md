# Phase 2B — saved certificate print preparation

2026-10-02. BUG-FUNC-0032 / CERTIFICATE-PRINT-ISSUANCE-001. Sol High. Successor to [certificate HTTP/SQL eligibility](PHASE_2B_CERTIFICATE_SQL_CHECK.md). Issue/Phase2B/release remain OPEN. No repeated Astra audit.

## Bounded change

Only certificate page and certificate-scoped watermark/identity CSS changed in product source. Official Print/save PDF requires an explicitly selected saved Issued certificate with complete identity/title/theme/calendar date/optional batch/notes and resolvable learner/batch names. Unknown/missing/non-Issued/Revoked/Replaced records cannot authorize the button or its directly invoked callback. No default first-register-row guess. A confirmed issuance selects its returned saved ID only after successful register readback. A new attempted issuance clears prior print selection;HTTP failure/uncertainty/malformed acknowledgement/failed readback cannot silently substitute an older certificate. Existing saved records can be explicitly selected later if valid.

The preview uses that saved row rather than the mutable creation draft:learner ID,class/batch,title,theme,date,note,number,verification code and status are tied to the record. Independent certificates do not borrow a draft class. Number/code/status now appear on the certificate itself. Every non-approved view carries PREVIEW — NOT AN ISSUED PRINT text plus a diagonal CSS watermark,including native manual print intent. Unsaved draft edits cannot change a selected saved preview. Empty draft date no longer renders a current-time expression during initial rendering. Actual watermark visibility/manual print CSS is still a browser/PDF gate,not proved by inspecting JSX text.

Each official print request re-fetches certificates,students,batches and branding in the already selected academy with no-store,checks all responses,then resolves/clones a complete Issued snapshot. No print POST,extra issuance or enrollment mutation. Revocation/replacement/removal seen in this read blocks printing;HTTP/network/JSON/array/required data failures print nothing and retain creation drafts. A page-local synchronous lock blocks duplicate print/issuance/refresh/saved-selection callbacks while reading/printing. Branding save/upload handlers and buttons respect the same print lock;native branding inputs disable while busy. This is not a new shared control or server access policy.

React renders the verified snapshot;an effect subscribes to afterprint and schedules the browser print call in a microtask with cleanup/one-view guards. Afterprint or the explicit Close print preparation recovery clears official approval,returns to a watermarked preview and unlocks controls. Native print failure also clears approval/unlocks. Notices say the device decides whether paper/PDF was produced,not that a file was saved. Microtask/event/cleanup intent is source and controlled-hook evidence only;real React commit/StrictMode/unmount/browser gesture/dialog lifecycle requires browser verification.

Important existing data limitation:Certificate stores learner/batch IDs and certificate fields,not original learner names,class names,academy branding or signatory snapshots. Preview uses last-loaded saved reference/branding data;official preparation uses freshly fetched saved references/branding,never their unsaved editor values. A later legitimate rename/branding change can therefore alter a reprint. This slice does not claim historical name/logo/signature immutability,cryptographic validity/public verification,API print entitlement,or change schema. Status/reference changes between separate reads and dialog opening remain a race gate.
