## Cause and narrow repair

The create page sends embedded JSON with lowercase day/startTime; the independent default JsonSerializer parser expected Day/StartTime. Case mismatch produced null member values and a validation400. Lists containing null caused an unchecked dereference before Apply/SaveChanges, resulting in sanitized generic500 in the real Testing pipeline. These Batch findings do **not** establish the cause of the historical Teacher production null error or a post-save failure.

[BatchesController](../../apps/api/Controllers/BatchesController.cs) now uses explicit PropertyNameCaseInsensitive options for that nested parser only and checks nullable list elements before their members. Pascal/camel/mixed property names work. The valid-day allowlist, TimeOnly.TryParse behavior, invalid-shape400 messages, empty-array rejection, required Online/Hybrid link checks, other business validations, replacement DTOs, Apply, raw string storage and existing future-session synchronization are unchanged. No broad catch swallowing or validation weakening.

[Batch setup](../../apps/web/src/app/batches/page.tsx) sends null for no selected teaching days instead of the invalid explicit empty-array string. Existing optional API behavior permits property omission/null/blank. A nonblank JSON string containing null or an empty array still fails; invalid selected entries are not silently discarded. The previous preservation helper/summary changes remain intact; no global form feedback/reset or layout fixes are included.
