# Phase 2B — certificate enrollment API repair

2026-10-02. BUG-DATA-0046 / CERTIFICATE-ENROLLMENT-001. Continue Sol High. This implements one accepted audit finding, not a repeated Astra audit. Issue/Phase2B/release remain OPEN.

## Approved scope and implementation

The user answered the policy question: **Active or Completed only**, including Completed history in an inactive batch. Certificates without a batch remain allowed. One four-line guard in CertificatesController.Issue now requires an exact academy/student/batch enrollment in either status before creating a linked certificate. Comparison is case-insensitive because the existing enrollment editor accepts and stores mixed-case statuses. Other statuses do not qualify. Existing student/batch academy guards run first and retain their errors.

No extra enrollment-date, student activation, batch activation, completion-date or certificate-date rule was authorized or introduced. This is relationship/status eligibility, not proof of attendance or completion of all course requirements. Existing inactive-person behavior remains. Nullable BatchId/Notes, historical IssuedDate, title trimming, theme/artwork defaults, server IDs/verification code,201/location/summary and domain audit remain unchanged. No frontend/schema/DTO/module/authorization/shared-control/migration changes. BUG-FUNC-0032 print/preview-before-issuance is separate and unmodified.
