## Repair

[Batch page](../../apps/web/src/app/batches/page.tsx) now gives create/edit/deactivate/reactivate confirmations that remain through workspace refresh, with role=status notices on setup and overview. A confirmed write followed by HTTP/network/JSON readback failure retains the confirmation and adds guidance to refresh the list. Readback decodes all four responses before applying their data, avoiding partially applied catalogue/list updates when one JSON response fails.

Successful create clears all per-batch inputs back to their initial defaults: name, code, branch, capacity10, waitlist0, Offline delivery, Group class,60-minute sessions,1 session/week, meeting link/days/times, room, enrolment status Open and start date. Academy/course context remains selected. A subsequent create has no stale teaching days/link or class settings. Successful edit closes its editor; failed or unconfirmed writes preserve all create details and an open edit's details.

Network/5xx writes explicitly say the save/update is **not confirmed**, advise checking the list before trying again, and do not automatically retry a potentially committed mutation. Definite rejected responses show failure, retain details and do not perform a success refresh. All paths release pending state in finally, including network exceptions. Blank names/missing context do not produce requests. Existing POST and complete-record PUT payloads, optional schedule behavior and preservation helper remain unchanged.

An in-flight ref blocks duplicate/opposing requests, including repeated invocation of the same create callback before React renders pending state. Pending state continues through save and readback. All mutation buttons and the academy selector are disabled; academy changes/cancel are also guarded in callbacks. Native fieldsets disable form/editor inputs and the nested non-portalled date picker. Custom select controls receive explicit disabled props because their menus portal outside those fieldsets. Fieldset styles preserve existing panel padding/layout; no shared date/select control or global CSS was changed.

These are in-page interaction guards, not server idempotency, cross-tab locking or optimistic concurrency. Setup stays on its screen with reset fields and refreshed directory; no new route redirect, browser-history or automatic-scroll behavior is claimed.
