## Implemented

- The existing `PrepareAccountReviewAsync` now compares observations to the **first protected account review for the same OAuth exchange**. It checks the baseline's protected integrity, academy/actor/exchange/binding/provider/generation/registration/security-stamp context and revision order. Subject and account component are compared exactly, including null and case; a refresh is not allowed to silently switch identities.
- This baseline is a continuity constraint, not a grant of authority. It remains relevant if its human confirmation was never completed or its confirmation window expired; it does not make an expired review usable or authorize the account. New observations still require the existing current-authority/source/fence/token-expiry checks and a fresh explicit confirmation. If no prior observation exists, the first review establishes a new unconfirmed baseline; no account match is fabricated.
- A mismatch returns **409 ProviderAccountChangedReauthorizationRequired**, with no review material, identity values, write or review audit. Corrupt/incompatible baseline returns **409 AccountContinuityHistoryInvalid**, not a new baseline or ordinary duplicate. A changed account requires a separately authorized new sign-in/exchange and new human review. This does not automatically initiate that flow, prove ownership or unlock an uncertain Google grant.
- Read and confirmation revalidate the baseline too, preventing a previously prepared current review from bypassing history-integrity failure. This is not permission inheritance from historical conversation/memory or from another admin's review. Existing current initiating Owner/Admin, module/academy/role/security stamp, protected source/fence/generation/registration, expiry, version/hash and explicit confirmation remain authoritative.
- Reuses existing protected review history, unique `(ExchangeId, BindingVersion)`, composite FKs, CAS binding fences and required atomic review/confirmation audits. No schema or migration change. No historical data deletion, token access, new permissions, network calls, DI/public routes/tools or UI connection enablement. All provider readiness/operations remain unavailable. Google/Microsoft refresh paths are exercised; Zoom public refresh remains unqualified and is not fabricated for this feature.
- The query selects one earliest review, avoiding unbounded loading or an arbitrary cap on refresh history. Deleted protected history cannot be reconstructed by this method; approved retention/tamper-resistant evidence infrastructure is still a release gate. Legacy identity inconsistencies are denied rather than silently repaired. A new exchange may intentionally choose a different account, but remains unconfirmed/not connected and must pass independent account/academy association, directory/consent/entitlement and grant-isolation qualification.
