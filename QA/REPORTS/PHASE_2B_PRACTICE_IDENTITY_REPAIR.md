## Product contract

- Only PracticeLogsController changed in application code. POST keeps the route, HTTP200 and full PracticeLog response. A narrow CreatePracticeLogRequest accepts StudentId, nullable PracticeDate, MinutesPracticed, nullable FocusArea and Notes. Extra legacy entity properties are ignored, never applied. New ID, route AcademyId, Logged status, null teacher feedback/review time/update time and current UTC creation time are server-controlled.
- Creation requires an existing active student in the route academy. Empty/missing/foreign/inactive student IDs fail400 without writes. This follows PortalController.IsActiveStudent/CanAccessStudent, not a new enrollment requirement; practice logging is not batch-specific.
- Existing portal practice limits are applied:1–1440 minutes and no practice date after current UTC today. Omitted/null practice date defaults to UTC today; explicit historic dates are retained. No arbitrary earliest-date/backfill cutoff is invented: valid SQL/.NET DateOnly.MinValue remains permitted and is explicitly tested. No sum-per-day limit or new privileged override policy.
- Focus area/notes remain nullable/empty and are preserved verbatim, including whitespace, as in the existing administrative route.250/2000 character maxima follow mapped columns. Constructor-parameter DataAnnotations + matching controller checks cover HTTP validation and direct invocation; no property-target record annotations. Review metadata is absent from the create DTO.
- Multiple records on one day remain supported: the existing academy/student/date index is nonunique. New entries never upsert/replace previously reviewed work. List remains tenant-scoped and descending by practice date. Separate review behavior remains unchanged: scoped selected row, trimmed nullable feedback, Reviewed status and server review time; existing role/filter/module rules untouched. Student/Teacher portal code is unchanged.
