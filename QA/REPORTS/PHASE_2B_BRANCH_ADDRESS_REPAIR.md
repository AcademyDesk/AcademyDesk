## Cause and repair

The compact Branches editor omits address/postcode controls. Its edit and status requests were missing both values, while PUT replaces the complete branch and assigns null for omitted optional properties. GET also lacked street address. This combination silently erased saved details.

[BranchesController](../../apps/api/Controllers/BranchesController.cs) now returns AddressLine1 in list, create and update summaries; existing summary fields retain their order and the appended nullable constructor field is additive. [Branches page](../../apps/web/src/app/branches/page.tsx) retains AddressLine1 and PostalCode in its branch model and explicitly sends both during edit/deactivate/reactivate. Null optional values remain supported. No schema/migration, new route, permissions/module/inactive policy, layout or form-state changes.

The existing raw API replacement contract is unchanged: explicit null clears either optional field, and a third-party client that omits it still clears it. This is a repair of the current register workflow, not server-wide PATCH semantics, optimistic concurrency or protection against old cached clients. Already-erased production data is not restored by this change.
