# Phase 2B — Scheduling batch-default reset

2026-10-01, Sol High bounded repair of accepted [BUG-DATA-0037](../ISSUES/BUG-DATA-0037.md). Existing audit evidence reused, not a repeated Astra audit. Issue/Phase2B remain OPEN for browser/device/all-linked/critical release acceptance.

## Result and preserved contract

The [Schedule page](../../apps/web/src/app/schedule/page.tsx) now assigns **both** teacher and branch whenever the batch changes. Null/missing defaults and an empty batch selection clear the corresponding optional selector instead of retaining a previous batch's assignment. Teacher-only/branch-only defaults clear the opposite field. Initial automatic batch selection also populates its matching teacher/branch values.

Switching batches intentionally discards prior manual teacher/branch overrides; a deliberate override entered **after** the switch remains selected and is submitted. Selecting the unchanged batch leaves its deliberate override alone. Dates, delivery mode, location and lookup requests are unchanged by batch switching. Existing post-create refresh preserves a selected batch and its deliberate overrides.

No API/security/schema/migration/CSS, calendar or Teacher portal changed. The existing [session API](../../apps/api/Controllers/ClassSessionsController.cs) still interprets optional null teacher/branch requests as **inherit the selected batch's default**, not forcibly remove an assigned default. The repair prevents accidental inheritance from a different batch; it does not introduce explicit-clear API semantics. The existing blank-selector wording and broader asynchronous loading/create/status feedback/clash-policy gaps remain separate work, not silently resolved here.
