## Protocol review and deliberate limitations

Google's documented UserInfo response supplies a stable `sub`; email is not a stable account identifier. This conservative parser also requires boolean `email_verified=true`, not an email-domain ownership inference. Microsoft `/me` is a delegated signed-in user read; the returned user GUID is an observation, **not proof of the configured directory**, active account, academy ownership or Teams meeting/license entitlement. Zoom own-user lookup provides user/account identifiers and account status; this candidate requires an active account. Missing/unsupported variants remain unavailable rather than inferred.

Primary sources checked: [Google UserInfo and identity fields](https://developers.google.com/identity/openid-connect/reference), [Microsoft Graph signed-in user](https://learn.microsoft.com/en-us/graph/api/user-get?view=graph-rest-1.0), [Zoom user API](https://developers.zoom.us/docs/api/users/). These support protocol candidates, not live interoperability, consent/license acceptance or a claim that all provider response variants are handled.

An observation is ephemeral and non-authoritative. It is deliberately NOT a durable academy-account association or permission/connection ticket. No provider identity changes Academy Desk's current user, role, academy, approval or meeting capabilities. `MeetingProviderBinding` still cannot be `Connected` under the existing SQL constraint, and all in-app connection controls remain disabled.
