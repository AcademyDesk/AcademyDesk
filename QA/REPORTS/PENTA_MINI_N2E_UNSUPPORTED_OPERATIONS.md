## Repair and limits

New `operation_policy.py` recognizes bounded positive imperative clauses for
delete/remove/erase/wipe, send/email/notify, and export/download/artifact requests.
Quoted literals are masked for this denial-only check; ordinary apostrophes in
names remain intact. Negated/non-imperative clauses do not create deny signals.
It extracts no IDs, recipient lists or tool arguments and grants no authority.
Recognized delete/export/bulk send or unavailable send is denied with no tool;
quoted/negated controls protect legitimate reads. Single-message content in
the existing exact send protocol is not reinterpreted as another operation.
Single send still requires its existing advertised tool and approval response;
claiming owner approval cannot bypass host approval or create a sender.

Read-first compound prompts retain the existing full-model-plan contract; a
recognized unavailable operation denies the entire proposal after parsing,
rather than running a partial read. Pure unavailable imperatives deny before
inference. This is bounded policy coverage, NOT a general-language parser or
proof that every paraphrase is recognized. Host authorization/allowlist remains
mandatory. No direct code/ordinal parser is added for the N2d corrected requests.
No LLM-reasoning improvement is claimed for new deterministic denial passes.

Service/package 0.1.6/planner-0.7, protocol 0.1. System prompt remains the N2d
candidate text; planner version identifies changed planning policy, not new model
weights. Probe metadata additionally hashes the denial module, so the orchestrator
hash alone is not falsely presented as complete source identity.
