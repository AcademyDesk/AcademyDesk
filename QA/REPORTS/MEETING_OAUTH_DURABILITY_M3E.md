## Implemented

- Durable, unique-per-attempt exchange admission for all three providers. A protected random permit and required audit commit before the coordinator can call the token transport. No SQL transaction remains open across HTTP; no automatic exchange retry.
- The original protected claim now binds the captured authorization-code hash. Replacing the private code or verifier, changing actor/academy/registration/security stamp/connection generation, or replaying an admitted attempt fails closed. Older claimed envelopes without the code hash cannot be admitted; reauthorization is required, not an invented migration proof.
- Exchange completion and its audit commit atomically. Structurally accepted tokens are encrypted using actor/academy/provider/attempt/exchange-bound Data Protection purposes and held as `TokensQuarantined`, explicitly account-unverified. Envelope integrity covers status, version, permit, deadline, registration, connection generation and security-stamp digest. Public/result serialization and diagnostic string representations cannot expose token material.
- Private token reads independently recheck current Identity/role/academy/module/stamp/expiry/registration/generation and commit their required audit before releasing credentials to trusted internal code. A binding compare-and-set participates in the same SQL transaction. Audit failure releases no credentials.
- Concurrent starts have one durable winner; concurrent completions have one token/audit commit. An expired/interrupted `Started` exchange recovers only to `OutcomeUnknown`, with required audit and no code reissue, provider retry or claimed success. Invalid or unprotectable evidence is retained, not silently retried or deleted.
- SQL schema adds tenant/provider/actor/attempt and binding foreign keys, a unique attempt index, status/version and positive-generation constraints. Populated downgrade is refused rather than deleting exchange/credential evidence. Denial-only HTTP no-write snapshots now include this table.
- Coordinator and stores remain internal, unregistered and without public routes or real provider call sites. Connections stay `VerificationRequired`, never `Connected`; existing in-app connection controls remain disabled. There is no credential-store provisioning, frontend, Mini, financial-domain or host permission expansion.
