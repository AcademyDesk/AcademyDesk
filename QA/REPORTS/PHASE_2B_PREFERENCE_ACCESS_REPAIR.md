## Policy and implementation

- Only `CommunicationPreferencesController` is added to the existing `communications.manage` permission mapping. Manager gains that permission; Operations and every other nonadministrator system role keep their existing permission set. No new permission name, general role bypass or global-filter change was introduced. Other communication controllers remain unmapped and denied to Manager.
- The action's second role-name gate is replaced by an active-account/same-academy guard, trusting the installed global filter for Owner/Admin, Manager, custom-role permissions and current academy/user access grants. A platform-owner flag's global bypass does not become a new consent grant: the old own-tenant/Owner-Admin-Manager role boundary is retained for flagged accounts. This does not repair inactive-user policy for unrelated controllers.
- New GET `/api/academies/{academyId}/communication-preferences/recipients` uses the same authorization/Engagement module gate as preference List/Save. It returns only scoped student/guardian ID, first name, last name, nullable email, ordered by name. No phone/address/DOB/finance/document/student-management records. Existing inactive contacts remain selectable, matching the unchanged Save eligibility and previous page data contract (e.g. recording an opt-out).
- The page replaces broad Students/Guardians GET dependencies with that lookup and validates the lookup shape before setting state. Selection and existing complete consent PUT payload remain unchanged. Save upsert/timestamps/notes normalization and global route audit remain unchanged. The page's existing success-message-clearing/readback failure behavior and selection-effect lint error are NOT repaired by this access slice.
