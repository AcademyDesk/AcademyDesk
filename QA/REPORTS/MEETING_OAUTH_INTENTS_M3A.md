## Implementation

- Separate `MeetingProviderBinding` records with unique academy/provider identity support GoogleWorkspace (Meet), Microsoft365 (Teams) and Zoom without overwriting the legacy Meeting draft or each other. Generation and optimistic concurrency version invalidate superseded intents. The current schema intentionally cannot represent a verified Connected account; statuses are NotConnected, AuthorizationPending, VerificationRequired and Disconnected. Credential/token/account verification fields are not invented by this migration.
- `MeetingOAuthAttempt` records bind academy, administrator, provider and binding generation to a five-minute single-use random state. Only SHA256 of raw state is stored in a queryable column. Data Protection binds the private envelope to academy/actor/provider/attempt purpose and covers immutable metadata, browser-binding hash, server registration fingerprint, Identity security-stamp hash, PKCE verifier, expiry and mutable claim state/version/timestamp. Integrity, expiry and exact current context are checked before claim.
- Internal `MeetingOAuthAttemptStore.PrepareAsync` independently checks current host Identity/active Owner-or-AcademyAdmin/academy/Engagement access, bounded provider/browser/fingerprint/expected-version input, and persists binding+attempt+required audit atomically. Cryptographic state and verifier use32random bytes each; S256 challenge generated deterministically. The browser binding and registration fingerprint are **server-only inputs**, not client/model authority; a future HTTP integration must generate/resolve them through the approved registration/cookie boundary.
- `ClaimAsync` rechecks current authority, actor/provider/academy, protected row integrity, expiry, exact browser/registration/security stamp, current connection generation/version and Pending state. It atomically claims the attempt once, advances the binding to **VerificationRequired**, and writes required audit. Replay, older reconnect intent, changed browser/app/security context, revoked authority, malformed/tampered state and cross-actor/tenant/provider claims fail closed. Claiming is not code exchange, provider consent proof, verified connection or permission to create meetings.
- Attempt and binding concurrency tokens protect competing callbacks and reconnect preparations. Global unique state-hash and composite academy/provider/binding foreign key prevent collisions and mismatched references. Required audit shares the same SQL SaveChanges transaction. Data-Protection material is excluded from JSON serialization and diagnostic ToString output; audit stores bounded actor/action/entity metadata, not state/browser/verifier/code/token contents.
- New migration `20261015143326_MeetingProviderOAuthIntents` adds only binding/attempt tables, constraints and indexes. Down refuses ANY authorization/binding evidence. Prior payroll nullable-PaidAtUtc, receipts, operations/outbox and existing dirty work remain intact. No Identity migration, provider credentials or changes to current connection/readiness markers.
- Store is internal, **not registered in DI**, and has no public initiation/callback route, authorization URL, HTTP client, cookie, code/token exchange, secret resolver, background worker or connected-account API. Existing UI controls remain disabled and existing meeting capabilities false. PKCE generation is host material preparation for future provider-specific qualification, not a claim of identical vendor protocol support.
