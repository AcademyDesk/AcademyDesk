- Google nonce is derived from server-generated protected attempt verifier/state hash/exact registration using a distinct versioned purpose. It is stable through authenticated resume and distinct across attempts. Only private ignored material exposes it for a future fixed authorization-request builder; no redirect or public browser adapter is enabled. The check derives the expected nonce again from the protected original attempt, never from a prompt/client value. Existing legacy attempts/tokens lacking matching evidence cannot pass this check.

General quarantined-token reads still do not release the ID token. Refresh does not retain old identity-token evidence; it cannot carry identity qualification forward to a new credential generation/version. - Private verifier fetches only Google's fixed public JWKS endpoint, with no bearer token/query/credential, bounded response/time/depth/key count and no application retry/cache. Future activation must use the existing secure handler (no proxy/redirect/cookie, normal TLS). No token-selected key URL, embedded key or discovery URL is followed. Tests substitute an in-process fixed transport and freshly generated synthetic RSA keys; **no real Google request or token is used**.
- Strict canonical compact/base64url/JSON shape and duplicate checks; RS256 only, bounded RSA public signing keys/unique kid/exponent, no private/alternate URL/certificate material or unsupported JOSE controls. The already-resolved IdentityModel token handler performs signature/issuer/audience/lifetime validation; no package change or custom signature algorithm is introduced. Additional host restrictions require exact registration audience/optional azp, expected subject, attempt nonce, access-token `at_hash`, integer bounded issue/expiry and nonfuture not-before. Multiple audiences are intentionally not supported by this narrow single-web-client profile. Email/domain/name are not ownership or authorization proof.
- Store requires the existing current confirmed-review/account-policy/source/continuity and initiating-admin authority checks, protected original claimed attempt/context, exact quarantined token/version. It rechecks host authority/policy/current source after asynchronous key/signature work and uses final exchange/review/binding concurrency fences with required audit in one SaveChanges transaction. Audit records fingerprints/contract/credential version and identity-only status, not raw token/nonce/subject/access token/keys or validator exceptions.

Audit is evidence of a bounded check, not an enabled credential, login/session, approval or reusable execution permit. A later disconnect may follow a completed unavailable read; execution never follows from it. Signature validity is not academy/domain ownership, consent completeness, license/meeting entitlement or cross-project grant-isolation proof.
