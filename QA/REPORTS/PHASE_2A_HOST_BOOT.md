# Phase 2A — isolated Testing host boot

Date: 2026-09-30. Base commit: `20bb6047f9edf733ac8e2a226621cc582ec54b3c`. This is the second bounded implementation slice after [the guard slice](PHASE_2A_ISOLATION_GUARD.md), not a new Phase 1 audit or a P0 reproduction.

## Changes and rationale

- Added `Microsoft.AspNetCore.Mvc.Testing` to the API test project and a `QaApiFactory` that starts the real `Program` with a generated QA run name, `Testing` environment, isolated content/web/storage/Data Protection roots, and the same approved SQL target for both DbContexts. It runs a planned-provider preflight before creating required content folders and repeats validation against the effective host configuration before `Program` can migrate or bootstrap.
- `Program.cs` now skips its early `wwwroot` directory creation only in `Testing`; all non-Testing behavior is unchanged. It exposes the conventional public partial `Program` entry point for `WebApplicationFactory`. This is necessary because ASP.NET requires the test content root to exist before executing `Program`, while the guard must authorize that folder first.
- Run-owned test folders receive a marker containing run ID and token digest. Their cleanup requires an exact matching marker and path check. The separate SQL cleanup guard still requires a database ownership marker; no fabricated SQL marker was used to authorize folder cleanup.

## Executed evidence

`dotnet test tests/AcademyDesk.Api.Tests/AcademyDesk.Api.Tests.csproj --no-restore --verbosity quiet`: **19 passed, 0 failed**. The six host tests include one successful real host start and five rejected final-configuration overrides; the additional folder-ownership test rejects a tampered marker. The positive test inspected the actual host environment, both resolved DbContext connection targets and mapped `/health` and `/api/auth/login` endpoints without opening SQL. The run-owned temporary folders and Data Protection key generated by that host were removed after marker-checked cleanup. Negative override tests confirmed the run folder was never created.

No database was created or migrated; no API request was sent, and no customer/dev/Azure data was read or written. The existing two student UI edits were preserved. The `Program.cs` change means the Phase 1 application fingerprint is no longer the current implementation fingerprint; this targeted host-testability diff is recorded here rather than reopening unchanged Phase 1 workflow reviews.
