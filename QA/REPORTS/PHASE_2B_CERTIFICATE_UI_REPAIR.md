# Phase 2B — certificate enrollment picker and issuance feedback

2026-10-02. BUG-DATA-0046 / CERTIFICATE-ENROLLMENT-001. Frontend successor to the accepted [API guard](PHASE_2B_CERTIFICATE_ENROLLMENT_REPAIR.md). Continue Sol High. Issue/Phase2B/release remain OPEN. No repeated Astra audit.

## Bounded change

Only apps/web/src/app/certificates/page.tsx changed in product source. The existing academy-scoped enrollments GET supplies eligibility; only batches with an exact selected-student/batch Active or Completed enrollment appear. Case-insensitive IDs/statuses align with the API policy. Completed history in an inactive batch remains visible; no extra activation/date policy. Duplicate enrollment rows do not duplicate options, unknown/malformed statuses and nonexistent referenced batches do not invent eligibility. This is not complete response-row schema validation or independent tenant enforcement; API authorization/scoping and final issuance guard remain authoritative.

Student and batch form selections share one controlled state. Changing the learner clears the old class immediately. Complete refresh preserves eligible selection, clears a newly ineligible class, and clears the previous class if a removed learner is replaced by the existing first-available-learner default. Other drafts remain. Empty class stays optional and sends null, explicitly described as an independent programme. No frontend entitlement creation or legacy certificate rewrite.

Initial/current records read students,batches,enrollments,certificates and branding; all requests use existing bearer-aware academyApi and no-store. Responses/arrays/basic branding shape are checked before updating datasets. No partial dataset replacement on HTTP/JSON/non-array failure. Initial failure does not claim an empty issued register and blocks issuance until Refresh records succeeds. Refresh retains the already selected academy rather than choosing a different first academy. Static subscription mapping puts enrollments in existing Core, like the prior students/batches dependency; no permission/module changes. Actual access proof is deferred to HTTP/SQL.

Page-local synchronous issuance/read lock plus disabled native fieldset/shared selector props prevent duplicates/opposing refreshes; student,batch and theme event handlers ignore pending changes, including an already-open portaled menu callback. Initial read also holds the lock. Notes/date reset only after a confirmed successful POST; title/theme/student/eligible class remain. Native fieldset uses display:contents and notes/button explicit full grid spans to retain the existing form-grid intent, without changing CSS/shared controls. Browser fieldset/grid/layout/accessibility behavior is not certified by controlled tests.

Explicit shared notice tones retain success after refreshing. A successful POST plus failed readback remains confirmed issuance with a refresh instruction; further issuance is blocked until readback recovers. HTTP rejection preserves the draft and displays the API message if supplied, with a generic fallback for malformed error JSON. Network uncertainty preserves drafts, warns that the write could not be confirmed and requires fresh records before retry. This is not API idempotency or proof that retry is safe if register readback is incomplete. Existing saved-certificate register remains unchanged on unsuccessful readback.

Branding/logo save handlers, certificate templates, preview/date presentation and Print/save PDF are unchanged. Separate BUG-FUNC-0032 print/preview-before-issuance remains pending; this task does not certify the printed draft as an issued credential. No backend/DTO/schema/module/auth/session/shared-control/CSS/storage changes.
