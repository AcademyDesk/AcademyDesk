# Phase 2B — Same-realm session-refresh coordination

2026-10-02; agreed Sol High allocation. Bounded successor to the accepted session-refresh repair, not a repeat of the Astra audit or provisioning matrix. Local laptop QA only.

## Result and scope

Overlapping expired requests previously started separate refreshes; later401s could return login failure after a peer renewed the session. The shared api.ts helper now shares one in-flight refresh per workspace and originating session generation/token pair. A successful receipt handles late401s from that pair. Each request retains its own method/body/headers and one replay maximum. Workspaces cannot borrow each other's refresh. Cancelling one waiter does not cancel others; all cancelled waiters abort the provider and permit a later fresh attempt. Identity-checked cleanup cannot remove a newer flight. Session generations reject pending renewal after sign-out/replacement, including same-credential re-login through the public helpers.

Coordination is confined to one JS realm. Cross-tab coordination/ABA, direct storage writes outside the public helpers, multi-round/long-running stress, revocation/password change/disabled identities, actual elapsed8h/30day lifetimes, browser routing and device acceptance remain OPEN. Successful receipts are bounded to one entry per workspace, not a new persisted credential store. Existing keys/legacy fallback, contracts, server policies/lifetimes and all prior application repairs remain unchanged.
