## Contract and policy

- POST keeps its route, HTTP200 success and original AssignmentSubmission response shape. Input is now a narrow CreateAssignmentSubmissionRequest: AssignmentId, StudentId, nullable ResponseText. Extra legacy entity fields are ignored, not trusted or applied. New ID, route AcademyId, Submitted status, null TeacherFeedback/UpdatedAtUtc and UTC SubmittedAtUtc/CreatedAtUtc are server-owned.
- Same-tenant student must exist; assignment must be same-tenant and published, with an existing same-tenant batch; a private assignment must target the requested learner; enrollment must match academy/student/assignment batch with Status Active. This follows the existing PortalController submission publication/private-target/Active-enrollment rules, adding independently scoped existence guards for legacy invalid references. No privileged unpublished/wrong-learner backfill override is invented; one would need an explicit approved/audited contract.
- No additional inactive-student/inactive-batch or enrollment-date/due-date policy was inferred. Those flags/dates are not part of the existing portal submission eligibility gate. A controller test explicitly records this limit. This is not a claim that every broader eligibility policy is release-approved.
- Nullable/empty response remains supported for the administrative route. Text is preserved verbatim, including whitespace; maximum4000 characters matches the existing mapped column limit, enforced both through model validation and inside the controller. Empty/malformed IDs or invalid binding get400. Friendly400/409 messages expose no foreign names.
- Existing unique academy/assignment/student key retained. Duplicate POST returns409 without replacing stored work/feedback or adding an audit. SQL2601/2627 races detach the unsaved row, verify the same scoped key actually exists, then return409; unrelated SQL failures are rethrown rather than silently treated as duplicates. No migration, new permission, route or shared filter behavior.
- Last slice's contextual GET/review PATCH and frontend are unchanged. Student/Teacher portal submission, attachment storage and review permissions were not redesigned.
